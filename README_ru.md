# zip_project 📦

Универсальная консольная утилита на Python для автоматической архивации и составления списков файлов ваших инженерных и программных проектов. Отлично подходит для быстрого создания бэкапов исходного кода, подготовки релизов или очистки проектов от временного мусора (вроде `__pycache__`, `.venv`, `.git`) перед их пересылкой.

---

## 🚀 Основные возможности

*   **Умный поиск конфига**: Автоматически ищет `zip_project.yaml` в папке с исполняемым файлом, затем в текущей рабочей папке. При отсутствии создаёт шаблон.
*   **Гибкая фильтрация**: Исключайте мусор по **glob-паттернам** (с поддержкой `**` для рекурсивного обхода), по расширениям, по размеру и дате изменения файлов.
*   **Два режима работы**: Создавайте текстовый манифест (plain, JSON, CSV) с метаданными (размер, дата), упаковывайте в архив (zip или tar.gz) – или и то, и другое.
*   **Переопределение через CLI**: Все ключи конфига можно переопределить аргументами командной строки без правки YAML – идеально для CI/CD.
*   **Переменные окружения**: Используйте `${HOME}` или `$PROJECT_DIR` в значениях конфига для переносимости.
*   **Сухой запуск** (`--dry-run`): Покажет, какие файлы будут обработаны, без записи на диск.
*   **Полная портативность**: Компилируется в один `.exe` файл с помощью PyInstaller, работает без установки Python.

## ⚙️ Детальная настройка (`zip_project.yaml`)

Файл конфигурации использует формат YAML и создаётся автоматически при первом запуске в папке, где конфиг отсутствует.  
Ниже приведена **новая расширенная структура** со всеми доступными параметрами:

```yaml
# ==============================================================================
# ОБЩИЕ НАСТРОЙКИ
# ==============================================================================

# Имя проекта (опционально, для информации)
project_name: "MyProject"

# Базовая рабочая папка (абсолютный или относительный путь).
# Может быть строкой или списком путей – тогда сканирование будет вестись из нескольких корней.
# Пути интерпретируются относительно папки, в которой находится сам конфиг.
base_working_dir: "."

# Кодировка для чтения/записи файлов (по умолчанию utf-8)
encoding: "utf-8"

# Сухой запуск: true – только показать список файлов, ничего не записывать
dry_run: false

# ==============================================================================
# ЧТО СКАНИРОВАТЬ
# ==============================================================================

# Папки, которые нужно обойти рекурсивно (относительно base_working_dir)
scan_dirs:
  - "src"
  - "modules"

# Конкретные файлы, которые нужно включить (помимо сканирования папок)
single_files:
  - "main.py"
  - "config.py"

# Расширения файлов, которые включаются в результат (если пусто – все файлы)
extensions:
  - ".py"
  - ".yaml"

# ==============================================================================
# ИСКЛЮЧЕНИЯ (GLOB-ПАТТЕРНЫ)
# ==============================================================================

# Паттерны для исключения – поддерживаются ** (любая вложенность), * и ?
exclude_patterns:
  - "**/__pycache__"
  - "**/*.pyc"
  - "**/.venv"
  - "**/venv"
  - "**/.git"
  - "**/temp/*"
  - "**/local_settings.py"
  - "**/.env"

# Дополнительно – исключать файлы с определёнными расширениями
exclude_extensions:
  - ".log"
  - ".tmp"

# ==============================================================================
# ОГРАНИЧЕНИЯ ПО РАЗМЕРУ И ДАТЕ
# ==============================================================================

# Максимальный размер файла в МБ (null – без ограничений)
max_file_size_mb: 10

# Минимальный возраст файла в днях (0 – только сегодняшние, null – все)
min_file_age_days: null

# ==============================================================================
# ВЫХОДНОЙ МАНИФЕСТ (СПИСОК ФАЙЛОВ)
# ==============================================================================

manifest:
  # Имя файла для списка
  file: "project_list.txt"

  # Формат: plain (простой список), json, csv
  format: "plain"

  # Включать ли метаданные (размер и дату модификации) в манифест
  include_metadata: false

# ==============================================================================
# АРХИВАЦИЯ
# ==============================================================================

archive:
  # Включить создание архива
  enabled: true

  # Имя архивного файла (может включать подпапки)
  file: "arch/project_backup.zip"

  # Формат: zip или tar.gz
  format: "zip"

  # Уровень сжатия (0 – без сжатия, 9 – максимальное)
  compression_level: 6

  # Пароль для ZIP-архива (пока экспериментально, может не поддерживаться)
  password: null
```

## 🛠️ Новые возможности в деталях

### 🌐 Glob-паттерны
Теперь вы можете исключать целые ветки файловой системы одним паттерном:
- `"**/__pycache__"` – исключит все папки `__pycache__` на любой глубине.
- `"tests/**/temp/*"` – исключит все временные файлы внутри папок `temp`, расположенных в любом подкаталоге `tests`.
- `"*.tmp"` – исключит файлы с расширением `.tmp` в корне (но не во вложенных папках, если не добавить `**`).

### 📦 Множественные базовые директории
Если указать `base_working_dir` как список, например:
```yaml
base_working_dir:
  - "backend"
  - "frontend"
```
то сканирование будет выполняться из каждой указанной папки, а относительные пути в манифесте и архиве будут строиться относительно соответствующей базы.

### 📄 Форматы манифеста
- **plain** – каждая строка содержит относительный путь к файлу.
- **json** – структурированный список объектов (если включены метаданные – каждый объект содержит `path`, `size`, `mtime`).
- **csv** – таблица с колонками `path`, `size`, `mtime` (если метаданные включены).

### ⏱️ Фильтрация по дате и размеру
- `max_file_size_mb: 5` – исключит файлы больше 5 МБ.
- `min_file_age_days: 30` – включит только файлы, изменённые за последние 30 дней (0 – только сегодня).

### 🔒 Переменные окружения
В любом строковом значении конфига можно использовать `${VAR}` или `$VAR` – они будут заменены на значения из `os.environ`. Это удобно для указания путей к проектам в разных окружениях.

## 💻 Запуск и использование

### Поиск конфига (порядок)
1. **Явно указанный аргумент** – `zip_project.exe /path/to/config.yaml`.
2. **Рядом с исполняемым файлом** (или скриптом) – `./zip_project.yaml`.
3. **В текущей рабочей папке** – `./zip_project.yaml`.
4. Если ничего не найдено – создаётся шаблон в текущей рабочей папке.

### Базовый запуск
```bash
zip_project                          # использует найденный или созданный конфиг
zip_project my_config.yaml           # явно указать конфиг
```

### Аргументы командной строки (CLI-переопределения)
Все следующие параметры **имеют приоритет** над значениями из YAML:

| Аргумент | Описание | Пример |
|----------|----------|--------|
| `--base-dir DIR` | Переопределяет `base_working_dir` | `--base-dir ./src` |
| `--include-dir DIR` | Добавляет папку для сканирования (можно повторять) | `--include-dir lib --include-dir tests` |
| `--exclude PATTERN` | Добавляет паттерн исключения (можно повторять) | `--exclude "**/old" --exclude "*.tmp"` |
| `--output FILE` | Переопределяет имя файла манифеста | `--output files.txt` |
| `--zip` | Включает создание архива (даже если в конфиге `enabled: false`) | `--zip` |
| `--dry-run` | Только показать список файлов, ничего не записывать | `--dry-run` |

**Примеры:**
```bash
# Использовать конфиг, но изменить базовую папку и добавить исключение
zip_project --base-dir ./project --exclude "**/backup"

# Включить архивацию и сухой запуск
zip_project --zip --dry-run

# Переопределить выходной файл и добавить папку сканирования
zip_project my_config.yaml --output list.txt --include-dir extra
```

### Приоритет настроек
**CLI-аргументы > переменные окружения > значения из YAML > дефолты**

## 🧪 Пример работы

**Структура проекта:**
```
📁 my_project/
├── 📁 src/
│   ├── main.py
│   └── utils.py
├── 📁 __pycache__/       (будет исключено)
├── 📁 .venv/             (будет исключено)
├── .env                  (будет исключено)
└── zip_project.yaml
```

**Конфиг:**
```yaml
base_working_dir: "."
scan_dirs: ["."]
extensions: [".py"]
exclude_patterns: ["**/__pycache__", "**/.venv", "**/.env"]
archive:
  enabled: true
  file: "backup.zip"
```

**Результат:**
- Создастся `backup.zip`, содержащий `src/main.py` и `src/utils.py`.
- Также создастся `project_list.txt` (имя по умолчанию) со списком этих файлов.

## 📦 Компиляция в EXE (для разработчика)

### Установка зависимостей
Перед компиляцией установите необходимые пакеты:
```bash
pip install pyyaml pydantic
```

### Сборка с PyInstaller
```bash
pyinstaller --onefile --hidden-import yaml --hidden-import pydantic --name zip_project run.py
```
Рекомендуется указать `--distpath` для сохранения в нужную папку утилит, например:
```bash
pyinstaller --onefile --distpath D:\Utils --hidden-import yaml --hidden-import pydantic --name zip_project run.py
```

Или, например под `Linux`

```bash
pyinstaller --onefile --distpath ~/.local/bin --hidden-import yaml --hidden-import pydantic --name zip_project run.py
```

### Быстрая пересборка через `.spec`
При первой компиляции создаётся файл `zip_project.spec`. При последующих изменениях кода достаточно выполнить:
```bash
pyinstaller zip_project.spec
```
Все настройки (пути, скрытые импорты, флаги) будут подхвачены автоматически.

## ❓ Часто задаваемые вопросы

**Как исключить системные файлы вроде `.DS_Store`?**  
Добавьте в `exclude_patterns` строку `"**/.DS_Store"`.

**Можно ли использовать конфиг без архива, только список?**  
Да, установите `archive.enabled: false` или не указывайте `--zip`.

**Что делать, если нужно обработать файлы из нескольких несвязанных папок?**  
Используйте `base_working_dir` как список, либо укажите несколько `--include-dir`.

**Как посмотреть, какие файлы попадут до реального запуска?**  
Включите `dry_run: true` в конфиге или передайте `--dry-run` в CLI.
